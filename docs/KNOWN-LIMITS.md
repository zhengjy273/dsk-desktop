## 〇、v1.1.0 新增：限额可视化

站点（chat.deepseek.com）2026-11-13 起上线了整套额度限制，但**页面上几乎看不到任何数字**：
额度耗尽只有一个提示条，重新生成/修改次数超限只弹一次 toast，禁言只在你发言被拒时才知道。
v1.1.0 把这些**明文显示**出来。

| 显示项 | 数据来源（只读观测） | 显示位置 |
|---|---|---|
| 模型额度 / 禁言状态 / 服务端文案 | `GET /api/v0/chat/status` 响应体 | 托盘 tooltip、托盘菜单账号行、输入框右上角浮层 |
| 单次输入上限（字数） | `GET /api/v0/client/settings?scope=model` 的 `model_configs` → `input_character_limit` | 同上 |
| 本会话累计已用 token | SSE 的 `accumulated_token_usage`（累计值，**含结束时的路径补丁帧**）/ `history_messages` | AI 生成标识**后面**（追加）、浮层 |

> v1.1.2 起**不再显示**重新生成/修改次数。原因：站点不下发计数，只能数页面自己发出的
> `/chat/regenerate`、`/chat/edit_message` 请求或数 `history_messages` 的分支关系，
> 两者都可能与实际不符（分支可能被删、请求可能失败重试），用户判断"拿不到准确剩余次数"，
> 因此整块移除；`QuotaView` 里相关字段保留但不再展示，托盘 tooltip 也同步去掉。

**实现方式与合规**：沿用 M2 的 `webContents.debugger` **只读**观测通道，解析页面**自己已经发出**的
GET 响应 —— 不新增请求、不重放、不构造 `x-ds-pow-response`（R2）；注入脚本不读 `.value`、
不碰 `localStorage`/cookie（R1），单测与运行期自检都有机器断言。

### 三个口径上的**事实限制**（不是 bug）

| 项 | 事实 | 为什么这样处理 |
|---|---|---|
| **单会话"剩余总量"** | 站点**没有**下发"本会话总量/剩余量"任何字段（前端只有 `accumulated_token_usage` 一个累计值）。 | 只显示**已用量**（`本会话已用 N tokens`）。任何"剩余 X"都必须自己编一个总量，会误导你。 |
| **重新生成/修改次数** | 站点不下发计数。只能数页面自己发出的请求（点一次 +1），或数 `history_messages` 的分支关系（前端口径 = 分支兄弟数-1）。 | **v1.1.2 起整块移除**（用户判断拿不到准确剩余次数）。曾实现过"剩余 X/Y"，数字确实会随操作递减，但分支被清理/请求重试时会漂移，不如不显示。 |
| **单次输入"实时字数"** | 可以数 textarea 长度，但那要读输入框内容（R1 红线附近）。 | 只显示**上限值**（实测 `2,621,440 字`），不追踪实时字数。 |

### 已用次数曾是怎么算的（v1.1.2 已移除，留档）

> 这一段记录曾经的实现，代码里 `QuotaView.regenerateUsed/editUsed/actionCountsEstimated`
> 与 `classifyQuotaAction`/`parseHistoryActionUsage` 仍在、单测也仍在，只是**不再展示**。
> 若将来站点肯下发权威计数，可以低成本恢复显示。

1. **即时通道**：观测页面发出的 `/chat/regenerate`、`/chat/edit_message` 请求，点一次 +1。
   实测这两个请求**可能没有请求体**，曾因 `postData === ''` 直接 return 而整次丢失 —— 已修。
2. **全量校准**：`history_messages` 返回真实消息时，按 `parent_id` 分组数分支兄弟数，得到该会话的权威已用次数，**覆盖**即时累加值。
3. **落盘**：按会话记进 `<账号>.sessions.json` 的 `regenerateUsed`/`editUsed`。否则重开应用次数归零，看起来像"额度回满了"。
4. 会话 id 变化时重置内存计数（次数是每会话量，跨会话带过去会算错）。


### 其他行为说明

- **只有页面可见时**站点才轮询额度（前端 `canFetch` 判 `visibilityState`）。所以窗口最小化/隐藏期间额度不会更新，恢复后约 5 分钟内刷新一次。
- **当前账号实时、其余账号显示缓存**：每个账号的额度落盘在 `%APPDATA%\dsk-desktop\quota\<账号>.json`，切到别的账号后旧账号显示上次登录时的值并标「缓存」；从未登录过的显示「未知」。
- **会话用量额外按会话缓存**：`history_messages` 命中服务端缓存时会返回**空** `chat_messages`（实测常见，398~400 字符），那一刻拿不到用量。每次观测到的用量按会话 id 记进 `%APPDATA%\dsk-desktop\quota\<账号>.sessions.json`（最多 200 条，超出按最久未更新淘汰），切回旧会话先读它兜底；没有缓存的新会话就先不显示（不显示 0）。
- **token 计数是"追加"不是"替换"**（v1.1.2 改）：`内容由 AI 生成，请仔细甄别` 原样保留，紧接着插入一个 `span`（` · 本会话已用 N tokens`）。这样既不遮挡 AI 生成标识（R3 不再是折中），站点改文案时也不会把我们的片段一起改掉 —— 锚点找不到就只是不显示。
- **浮层可拖动**（v1.1.2 新增）：按住顶部小条拖动；位置记在主进程（`overlayPos`）与页面内 `manualPos` 两处，**切会话/重载页面都不变**。浮层展开后底部有「恢复默认位置」按钮，点它回到"贴输入框右上角"的跟随状态（不再固定坐标，输入框动它就跟着动）。
  - 拖动与点击区分：位移超过 2px 才算拖动，松手后吞掉那一次 click，避免"想拖一下却把面板展开了"。
- **浮层贴合输入栏**（v1.1.1 起，v1.1.2 加固）：贴在**输入框容器右上角**（沿 textarea 父链找同时含发送按钮的容器），不压发送按钮。展开/收起时用 `getBoundingClientRect()` 重新量（**不能用 `offsetWidth/offsetHeight`**，刚切 class 时它们是旧值 —— 这正是 v1.1.1"展开后不贴合"的原因），并用 `requestAnimationFrame` + 60ms 各补一次；浮层自身尺寸变化由 `ResizeObserver` 兜底。找不到输入框时退回右下角。
- **迷你窗不显示浮层**（v1.1.2 新增）：迷你窗空间小，浮层整块 `display:none`（不卸载，退出迷你窗立刻恢复）。托盘 tooltip 与账号行的额度照常显示。
- **SPA 切会话**（v1.1.2 修）：站点点侧栏切会话走 `history.pushState`，**不触发 `did-navigate`**，只触发 `did-navigate-in-page`。漏掉它会让会话 id 永远停在上一次加载的地址 —— 表现为"切会话后用量/位置还是上一个会话的"。已在 `ContentView` 补上该监听。
- **最大化后页面跟着变尺寸**（v1.1.3 修）：窗口最大化时客户区从 1166×784 变成 1462×843，但 `resize` 事件只在"尺寸变了"时发一次，不保证"变完了" —— 全屏/最大化过渡期间那一刻 `getContentBounds()` 可能还是旧值，视图被定成旧尺寸后再没人纠正，于是页面比窗口小一圈、底部露一条黑带（用户截图实测）。现在 `resize` 之外还监听 `resized`（窗口**结束**调整后才发），并在 maximize/enter-full-screen/unmaximize/leave-full-screen/restore 每条路径都调 `pinViewBounds()`（同步一次 + 60/180/420/900ms 各补一次）。
- **虚拟列表**：站点消息列表是虚拟滚动的，滚出视口的回答会被销毁重建。输入栏那行在输入框重建后由 MutationObserver 补上，切会话后会重新定位锚点。
- **token 恒为 0 曾是解析 bug**（v1.1.2 修）：站点流结束发的是**路径补丁帧**而不是快照帧 ——
  `{"p":"response","o":"BATCH","v":[{"p":"accumulated_token_usage","v":110},{"p":"quasi_status","v":"FINISHED"}]}`，
  键 `p` 是字段路径、`v` 才是值。旧实现只认 `key === 'accumulated_token_usage'` 的快照写法，所以只读到流式过程中的 `0`。现已在 `sse-parser.collectAccumulatedTokens` 与 `quota-parser.maxAccumulatedTokens` 两处都认补丁帧。
- **「清除本地归档数据…」会一并清额度缓存**（v1.1.5 改）：原来只清 `%APPDATA%\dsk-desktop\mirror\`，现在连 `%APPDATA%\dsk-desktop\quota\` 下的 `<账号>.json` / `<账号>.sessions.json` 一起删，确认框里也写明了。清完额度会在页面下次同步（约 5 分钟内）重新采集。
- **浮层「恢复默认位置」现在能跨重载**（v1.1.5 修）：页面里点按钮后除了清 `manualPos`，还会向主进程发一条固定标记（走 `console-message` 只读旁路，不带任何页面数据），主进程据此把 `overlayPos` 也清掉。之前只清页面侧，主进程还留着旧坐标，**页面一重载就把位置灌回来**（审查实测：点了恢复默认，刷新后又跑回原处）。
- **最小化期间不重算视图尺寸**：`syncBounds()` 在 `isMinimized()` 时直接返回 —— 最小化时 Windows 报的 bounds 是异常值（实测 `x=-15994, y=-15971, height=0`），拿它设视图会把页面压扁。
- **页面里的外部跳转被拦截**（v1.1.5 补）：`setWindowOpenHandler` 只覆盖 `window.open` / `target=_blank`，主框架 `location.href` 跳到站外会直接加载进壳里、标题还挂着 "DeepSeek Chat"。现在 `will-navigate` / `will-redirect` 也拦，改用系统浏览器打开。
- **`DSK_CAPTURE_SSE` 默认关闭**（v1.1.5 改）：原来是 `!== '0'` 即默认开启，会把真实对话流落盘到**工作区**的 `docs/m2-evidence/`。安装版跑起来不该往程序目录塞用户对话，改成 `=== '1'` 显式开启，只在探针/开发时用。
- **会话用量的归属保护**（v1.1.5 补）：流式回答结束时如果用户已经切到别的会话，SSE 里的累计值不该写到新会话上。现在先比对页面 URL 的会话 id，对不上就跳过；同会话内取 `max`（累计量单调，续流重放片段会让数字往回跳）。
- 关闭注入：目前没有开关。若想临时关掉，删掉 `src/inject/quota-overlay.ts` 的两处调用即可（托盘与浮层会一起消失，额度数据仍在日志里）。

## 一、不是 bug 的设计决定（不会改）

| 项 | 说明 |
|---|---|
| **没有标签页 / 没有"新建会话"按钮** | 站点自带侧边栏已承担会话管理。应用层再加一层重复、费内存，且实测引发一连串问题（并发加载被限流→新标签黑屏、误报通知）。会话请在**站点侧边栏**里切换。 |
| 关闭主窗口 = 隐藏到托盘 | 托盘常驻的预期行为；真正退出用托盘菜单的"退出"。 |
| 没有"关闭标签/关闭会话" | 同上，会话管理交给站点。 |
| **没有"回答完成"通知** | 用户决定取消（2026-10-10）。原因：原先用 DOM 静默启发式判定"本轮结束"，误报多（改窗口尺寸、点外链、切页都可能触发）、收益低。若将来要做，应基于网络通道的 SSE 精确信号，而不是猜 DOM。 |
| **迷你窗 ⇒ 必然置顶（单向联动）** | 迷你窗下窗口始终置顶；托盘里该项显示为"置顶窗口（迷你窗强制）"且**灰掉不可点** —— 也就是说**迷你窗状态下无法关闭置顶**（避免"勾着迷你窗却没置顶"的矛盾状态）。退出迷你窗后回到用户自己选择的状态。**反向不成立**：勾"置顶窗口"不会开启迷你窗。 |
| **托盘菜单结构（v1.1.4）** | 显示 / 隐藏 · 迷你窗 · 置顶窗口 · 查看本地归档… · 导出归档 · 清除本地归档数据… · 诊断（写日志）· 账号：<当前账号> · 额度摘要 · 退出。v1.1.4 按用户要求：**取消「导出页面快照」**（原位由「清除本地归档数据…」接替）、导出归档**只出 Markdown**、标签里不再带"（结构化）"。归档查看器窗口里同样只剩「导出 Markdown」一个按钮。 |

## 四、已知坑与禁忌（改代码时注意）

| 坑 | 结论 |
|---|---|
| **注入脚本是模板字符串拼出来的 JS** | 变量插值的外层是模板字符串，所以**正则里的反斜杠要写两个**（`/(^|\\s)ds-message(\\s|$)/`）。写成单反斜杠会被模板吃掉，生成脚本里退化成 `s` —— 实测就是"回答徽标长期 0 处"的真凶。同理**注释里不要出现裸反引号**（会提前终止模板，vitest 报 `PARSE_ERROR`）。单测用 `new Function(script)` 兜底，语法错误在测试里就炸，而不是在页面上静默失败。 |
| **不要给开发期的 `electron.exe` 打图标**（resedit 等） | 实测：改写 exe 图标资源后，进程正常启动、窗口句柄也创建了，但 `show()` 之后窗口**始终 visible=false**（"应用起来了但没窗口"）。恢复干净 exe 立即恢复。任务栏图标留到 M3。 |
| Windows 下窗口**全屏/最大化/最小化**时 `setBounds` 会被忽略或基于垃圾值 | 三个状态都要先恢复：`normalizeWindowState()` 依次 `restore()` → `setFullScreen(false)` → `unmaximize()`。而且**恢复是异步的**：系统稍后会把窗口还原成"进入前尺寸"并**覆盖**刚设的 `setBounds`（用户实测：最大化→最小化→迷你窗，尺寸不对）→ 需要延时补钉（150/600ms）+ `restore`/`unmaximize`/`leave-full-screen` 事件兜底。任何"改窗口尺寸"的功能都要考虑这两层。 |
| 迷你窗状态必须与用户手动全屏/最大化**联动** | 用户在迷你窗状态下自己点最大化/全屏 → 视为放弃迷你窗状态，标记立即归位（否则之后点"迷你窗"想取消时，代码以为要"恢复原尺寸"而窗口仍全屏，尺寸逻辑会错乱 —— 用户实测）。已监听 `maximize` / `enter-full-screen` 事件。 |
| 迷你窗下**不可拉伸**（固定 380×520） | 进入时 `setResizable(false)`、取消时恢复 `true`。原因：用户拖拽拉伸会让 `mini` 标记与实际尺寸脱节，取消迷你窗时会跳到意外尺寸（用户实测）。**副作用（Windows 行为）**：`setResizable(false)` 会让最大化按钮一并变灰，因此迷你窗状态下按不了全屏 —— 取消迷你窗后恢复正常。 |
| 最小化期间**不要**同步视图 bounds | Windows 会把最小化窗口的 bounds 报告成异常值（坐标 -32000 一带），用它 `setBounds` 会把视图压成 1×1/异常位置 → 恢复后"黑屏"。`syncBounds()` 已加 `isMinimized()` 短路，恢复由 `restore` 事件补一次。 |
| Windows 会在**最小化时丢掉窗口置顶** | 恢复时必须重新 `setAlwaysOnTop`。已抽出 `applyAlwaysOnTop()` 统一处理（迷你窗永远置顶，否则跟随"置顶窗口"开关）。 |
| **窗口"正常尺寸"要自己记，不能现取 `getContentBounds()`** | 最小化时它返回 `x=-15994, y=-15971, height=0` 这种垃圾值；最大化时的值也不是"正常尺寸"。已在 resize/move 里维护 `lastNormalBounds`，并**排除最小化/最大化/全屏**与明显异常值（宽高<200、坐标<-10000）。 |
| **selftest 复核窗口行为必须异步** | 退出最小化/最大化是 Windows 消息级异步操作，同步断言读到的是"被还原覆盖前"的值 → 必然误报。已把该场景放进 `runMiniRestoreVerification()`（分步 + 等待），并让 `finishSelftest` 等它跑完再落盘。 |
| **删除账号必须记入 `removed`** | `personal`/`work` 是预置候选（`SUGGESTED_ACCOUNTS`），删除时若只从 `known` 移除，下次 `listKnownAccounts()` 又会加回来 → 用户看到"删不掉默认账号"。另外**当前账号不允许删**（会连正在用的登录态与归档一起清掉），需先切换到别的账号。 |
| **打包产物绝不能放在 `<workspace>` 目录树内** | 该目录树 DACL 有孤儿 SID + Low Mandatory Level + 无 AppContainer ACE → Chromium 沙箱以 `0x80000003`(STATUS_BREAKPOINT) 崩溃；NSIS 生成安装包那步也会 exit 2。`scripts/package.mjs` 已默认输出到 `%LOCALAPPDATA%\dsk-desktop-build`。 |
| 打包时 **PATH 里必须有 `pnpm`** | electron-builder 26 会调用 PATH 里的 pnpm 收集依赖树，而本机 pnpm 只在 DSH 内部路径（只有 `.mjs/.cjs`）→ 报 `No JSON content found in output`。`scripts/package.mjs` 会自动造 `.tools\pnpm.cmd` shim 并前置到 PATH。 |
| 打包版**入口要用 `.mjs` 包装层** | 直接把 `.ts` 当 `main` 字段入口，Electron 加载主模块时不走 Node 的 type-stripping 路径。现在 `main` 指向 `src/main/entry.mjs`（它 `import './main.ts'`）。开发期不受影响（launch.mjs 仍直接以 `.ts` 为参数）。 |
| Electron 主进程**不支持** TS 的参数属性 / enum / namespace / 装饰器 | 本项目直接跑 `.ts`（strip-only 类型剥离）。已加 `pnpm check:strip-only` 兜底。 |
| `app.setPath('userData')` 必须在 `requestSingleInstanceLock()` **之前** | 否则单实例锁基于错误目录。已修（踩过）。 |
| `ELECTRON_RUN_AS_NODE=1` 由 DSH 注入 shell | 任何启动 Electron 的入口都必须走 `scripts/launch.mjs`。 |
| Electron 默认**不发** `Sec-CH-UA` 系列头，且 UA 带 `Electron/44.x` | **当前运行时仍是 Electron 默认值** —— `src/session/fingerprint.ts` 只有纯函数与单测，主进程**未接线**（`setupSession()` 里没有 `webRequest.onBeforeSendHeaders`）。改写逻辑完整存在于实验脚本 `spike/main.mjs:200`，M0 的 V5a/V5b/V5c 是在那里跑出来的。按用户决定保持现状、只改文档；将来要真生效就把那段搬进 `setupSession()`。无论哪种方式，**不要**伪造 `Google Chrome` 品牌（会与 `navigator.userAgentData` 矛盾，反而更易被检测）。 |
| **注入脚本里的正则写在模板字符串内，必须写 `\\s`** | 源码里写 `/(^|\s)ds-message(\s|$)/` 经外层模板字符串转义后变成 `/(^|s)ds-message(s|$)/` —— 只匹配字母 s，实测**一个类名都匹配不到**（回答徽标长期 0 处的真凶）。单测现在会 `new Function(script)` 跑一遍，语法/转义错误在 CI 就暴露，不用等页面。 |
| **用户消息也带 `ds-message`** | 只按 `ds-message` 找回答会把徽标挂到你的提问下面（实测发生）。可靠区分是"回答正文走 `ds-markdown` 渲染"，用户消息没有。**不要**用哈希类名（`_63c77b1` 这种每次构建都变）或"有没有 textarea"（编辑态才有）来判断。 |
| 站点的操作栏按钮**没有 aria-label / title**（除朗读） | 想按无障碍标识找"重新生成"按钮会失败。真实点击要走 `Input.dispatchMouseEvent`（`scripts/cdp-click.mjs`）；页面内 `el.click()` 是合成事件，部分组件不响应。 |
| **`offsetWidth/offsetHeight` 在刚切 class 时是旧值** | 浮层展开时若用它们算位置，会按"收起时的高度"贴位 → 展开后浮在输入框上方很远或压住输入框（用户实测"展开后不贴合"）。必须用 `getBoundingClientRect()`，且在 `requestAnimationFrame` 与 60ms 后各补一次。 |
| **站点是 SPA，`did-navigate` 抓不到侧栏切会话** | 切换会话走 `history.pushState`，只触发 `did-navigate-in-page`。漏掉它 → 会话 id 永远停在上次加载的地址：按会话的 token 缓存取不到、浮层位置也不按会话重算（用户实测"切会话后数字不对"）。`ContentView` 两个事件都监听。 |
| **`history_messages` 命中缓存时 `chat_messages` 是空数组** | 返回 398~400 字符的 `{"chat_session":{…},"chat_messages":[],"cache_control":"MERGE"}`。这不是错误，是服务端缓存命中；别把它当"会话没消息"，也别据此显示 0 —— 应保留按会话缓存的上次观测值。 |
| **SSE 结束帧是"路径补丁"，不是快照** | `{"p":"response","o":"BATCH","v":[{"p":"accumulated_token_usage","v":110},{"p":"quasi_status","v":"FINISHED"}]}` —— 键 `p` 是字段路径、`v` 才是值。只认 `key === 'accumulated_token_usage'` 会一直读到流式过程中的 `0`（用户实测"token 始终为 0"的真凶）。 |
| **`resize` 不等于"尺寸已经变完"** | 最大化/全屏过渡期间 Windows 分几帧改窗口尺寸，`resize` 首次触发时 `getContentBounds()` 可能仍是旧值。只靠 `resize` 同步视图 → 视图停在旧尺寸、底部露黑带（用户实测）。必须再加 `resized`（结束事件），并在状态切换路径上做延时补钉。排查开关：`DSK_VIEW_DEBUG=1` 会打印 `[view-debug]`（含 `win` / `parent` / `prev` / `next` / `max` / `fs`）。 |

## 六、发现真 bug 时怎么反馈

把这两样给我就行：

1. **现象**：你点了什么 → 期望什么 → 实际什么（截图更好）；
2. **日志**：`logs\app.log`（如果应用还能启动）或 `docs\m1-evidence\t1-selftest.json`。

我拿到后会：读日志定位 → 给根因 → 修 + 加一条**自动化断言**（避免回归）→ 重启让你复测。

> 到目前为止已按这个流程修掉的问题（都有对应的自检断言）：黑屏（零标签 + 视图可见性）、
> 站点限流（单视图 + 连点合并）、V14 误报通知、迷你窗全屏失效、双击托盘只能恢复、
> 关闭标签导致侧栏会话闪烁、启动失败静默无窗口。
